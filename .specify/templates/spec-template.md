# Spec — <功能名>

> **spec 固定的是口径，不是实现。** 这里回答「要做成什么样、边界在哪」，不回答「代码怎么写」。
> 实现方案写在 `plan.md`。新玩法的规则以同目录 `gdd.md` 为准。

## 1. 要解决什么

一到两段话说清：现在是什么状态，玩家遇到什么问题，做完之后变成什么状态。

新玩法写明对应的 `gdd.md` 路径，以及用户确认的日期。

## 2. 玩家可见的行为

用玩家视角描述，不要出现类名和函数名。

- 玩家在 <什么界面> 做 <什么操作>，看到 <什么结果>
- 失败时看到什么提示
